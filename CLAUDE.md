## 1. How the site is built and deployed

- **Static HTML site.** No framework, no React. Plain `.html` files + prebuilt `assets/tailwind.css`. Pages are generated from data files by Node build scripts.
- **Hosting:** GitHub Pages, behind **Cloudflare** (DNS + CDN). Repo: `github.com/eugeneteo88/jte-recruit-website`, branch `main`.
- **Deploy is automatic:** every push to `main` triggers `.github/workflows/deploy.yml` → runs `npm run build` → publishes the whole repo to GitHub Pages (orphan `gh-pages` branch, build tooling excluded). **So: commit + push to `main` = live in a few minutes.** No manual deploy step.
- 🔴 **SSL gotcha:** Cloudflare SSL mode MUST stay **"Full"** (not "Strict"). GitHub Pages' origin cert periodically looks invalid to Cloudflare; Strict then throws a **526 error** and the site goes down. If the site shows an SSL/526 error, the fix is Cloudflare dashboard → SSL/TLS → set encryption mode to **Full**. Eugene does this himself in the dashboard.

### Build commands (run from repo root, Node 22)
```
npm run blog      # regenerate blog index, per-article cards/forms, related blocks, sitemap from blog/posts.json
npm run build     # full build: blog + salary + review + updates + tailwind CSS
node scripts/qa-check.mjs   # MUST pass with FAIL: 0 before every commit (also WARN: 0 ideally)
```
After ANY content change, run `npm run blog` (or the relevant builder) then `node scripts/qa-check.mjs`. **Never commit with QA failures.**

### 🔴 Syncing before you commit
The CI runs a scheduled cron (`content-ops.yml`, Mon & Thu 08:00 SGT) that **commits `seo/data.json` refreshes directly to `main`** ("chore: refresh SEO dashboard data"). So `origin/main` often moves ahead of you. **Always `git fetch` and `git pull --ff-only` (or `--rebase`) before pushing.** Expect fast-forwards from those SEO-data commits; they are not conflicts.

## 2. The content / article pipeline

Articles ("Field Notes") live in `blog/<slug>/index.html`, driven by a single source of truth: **`blog/posts.json`** (array of `{slug, title, tag, excerpt, author, date, readTime, icon, draft}`).

### How scheduling works (important)
`scripts/build-blog.mjs` publishes a post **only when `date <= today` (Singapore time) AND `draft !== true`**. A future-dated post is fully built but kept **`noindex`** and **out of the blog index + sitemap** until its date arrives, then it **self-publishes** (and self-injects its lead-capture form) the next time the build runs. CI rebuilds on every push and on the cron, so scheduled posts go live on their date automatically.
- **To schedule:** set a future `date`, `draft: false`.
- **To freeze permanently** (keep the file, never publish): `draft: true`.
- **To publish now:** set `date` to today or earlier, `draft: false`, rebuild.

### How to build a new article
The assembler is `content-ops/build-article.mjs` → `buildArticle(contentObject, date)`. It clones a template and injects content, so you **never hand-write article HTML**. The content object shape (see the file for the exact schema):
`{ slug, title, metaDescription(≤160), h1(problem-led), dek, heroAlt, lead:[1-2 paras], sections:[{h2, paras:[], media?:[{type:'animation',html,caption}]}], callout, faq:[{q,a}×6], crossLinks:[{anchor,slug}], graphic:{type,title,items} }`
It auto-generates BlogPosting + FAQPage + BreadcrumbList JSON-LD, strips em-dashes, and funnels a CTA to `/contact`.

Each article gets **3 visuals**:
1. **Hero** — a candid Singapore photo generated by Gemini (`scripts/gemini-image.mjs`), then branded via `scripts/hero-graphic.mjs makeHero({eyebrow, headline(≤4 words), accent(≤3 words, gold italic), subtitle, bg, out})`. Save the raw photo to `assets/hero-bg/` so re-compositing later is free.
2. **In-brief graphic** — `scripts/graphic.mjs makeGraphic({type:'list'|'steps', eyebrow:'In brief', title, items, out})` (cream card, no photo, free).
3. **Animated step timeline** — `scripts/anim-svg.mjs animSteps({title, subtitle, steps:[], label})` returns an inline SMIL SVG; embed it in a section's `media:[{type:'animation', html, caption}]`.

A one-off batch builder pattern: write a script in `content-ops/` that imports `buildArticle`, `makeHero`, `makeGraphic`, `geminiImage`, `animSteps`; `mkdirSync` the `blog/<slug>/` dir **before** `makeHero` writes into it; guard Gemini calls with `existsSync` so re-runs don't re-bill; push new entries into `blog/posts.json`; then run `npm run blog` + `qa-check`. Delete the one-off script after. (The autonomous version is `content-ops/run.mjs`, dormant unless `OPENAI_API_KEY` is set.)

### 🔴 Image spend cap
Gemini image gen (`gemini-2.5-flash-image`, ~US$0.04/image) is capped at **US$20/month** (Eugene's rule). Log every generation in `content-ops/image-spend-log.md`. Re-compositing an already-generated photo is **free** (no API call). The `GEMINI_API_KEY` is a GitHub Actions secret — it is NOT in the repo. Write as **Eugene**: first-person, casual, friendly, plain English, short sentences, a bit of personality, honest, never corporate. Explain it like to a mate over coffee.

- Every article opens on the **employer's problem**, not a definition. Question-shaped H2s. Answer-first opening sentence (for answer engines). FAQ×6 with schema. 2-3 internal cross-links including, where it fits, the money page `/free-payroll-singapore/`.

## 4. The strategy (what the content is for)

- 🔴 **Payroll vs recruitment — don't confuse them.** The **payroll service is standalone and industry-agnostic** (ANY industry can park payroll with us). In practice it's driven by **contract/hourly placements, not permanent**, heaviest from **IT**, also **healthcare** and general contract staffing. **Engineering rarely parks payroll.** So payroll content targets "park your contract-staff payroll" broadly (IT/healthcare/contract angles), NOT "engineering payroll".
- **Recruitment service is per-industry with BOTH perm + contract** across engineering, healthcare, IT, logistics, manufacturing, commercial. Sector content sells recruitment and does NOT have to funnel to payroll.
- **Strongest payroll vein:** project/contract-staffing payroll — a 1-3 year project lands, headcount spikes, in-house HR gets buried, temp HR backfires, so they outsource payroll to us (near-$0, scales up and down, winds down cleanly).
- **Homepage:** Eugene likes the current design (horizontal scroll, image-led, simple, immediate). **Do NOT revamp it.** Image + few words that correlate, beats walls of text. Enhance with a section/button, don't redesign.

## 7. Gotchas

- **Tailwind is prebuilt/purged.** `assets/tailwind.css` only contains classes present at last build. If you use a utility that isn't compiled in (e.g. `space-x-6`, `sm:w-auto`), it silently does nothing — either run `npm run css` to recompile, or use a scoped `<style>` block. The deploy CI recompiles CSS, but local renders won't reflect new classes until you run `npm run css`.
- **Headless-Chrome screenshots:** `h-screen` heroes balloon in headless — cap `.h-screen{height:Npx}` for the shot. Render mobile at window-size 500 to avoid a ~497px crop artifact.
- **QA:** `node scripts/qa-check.mjs` checks em-dashes, Title Case, broken links, etc. Keep FAIL:0 WARN:0.
